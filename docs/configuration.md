# Configuration and running as a service

## Environment variables

| Variable | Default | Meaning |
|---|---|---|
| `HERDR_PORTAL_PORT` | `8787` | Loopback port (the host is always `127.0.0.1`) |
| `HERDR_PORTAL_STATE_DIR` | `~/Library/Application Support/herdr-portal` | Token (`secrets/portal-token`), `ledger.jsonl`, `tunnel.json`, `tunnel-url.txt` |
| `HERDR_PORTAL_LOG_DIR` | `~/Library/Logs/herdr-portal` | `audit.jsonl` and the service logs |
| `HERDR_BIN` | `herdr` on `PATH` | The Herdr CLI. Under launchd set an absolute path; if `herdr` is a version-manager shim, point at the real binary |
| `HERDR_PORTAL_DROP_DIR` | `<state dir>/inbox` | The only directory `put_file` writes to. Created with mode 0700 if missing; an existing one is not chmod'ed and must be owned by the portal user and not writable by others. It must support hard links (`create` mode uses `link(2)`) |
| `HERDR_PORTAL_HOSTS` | none | Extra allowed `Host` names, comma separated |
| `HERDR_PORTAL_TUNNEL_METRICS` | `127.0.0.1:20241` | Where `cloudflared` serves its metrics; the portal probes it for `/api/health`, and `portalctl diagnose` and the plugin's activity tab ask it how many connections the tunnel has. The plugin only asks `127.0.0.1:<port>` or `localhost:<port>`; for any other value it silently uses the default |
| `HERDR_PORTAL_TUNNEL_LOG` | the `cloudflared` log written to last: the portal's `tunnel.log` or the cloudflared service's own | Which `cloudflared` log `portalctl diagnose` reads for tunnel outages. A log named here is the only one read; if it cannot be read, the report says so. A portal tunnel job that keeps failing writes to `tunnel.log` every 10 s and so wins the choice between logs: remove that job ([tunnel.md](tunnel.md)) or name the service's log here |
| `CLOUDFLARED_BIN` | `cloudflared` on `PATH` | The tunnel binary. `portalctl install` adds the tunnel job only when this resolves to an absolute path of an executable; any other value (`none`, say) installs the portal alone |
| `HERDR_PORTAL_LAUNCHD_PREFIX` | `dev.herdr-portal` | launchd label of the portal (the tunnel adds `.tunnel`) |
| `HERDR_PORTAL_STRICT_VERSION` | unset (off) | `1` limits writes to the Herdr version proven live (0.9.5); otherwise any version whose schema fits is accepted. `portalctl install` copies it into the portal LaunchAgent (not the tunnel's) only when set to `1` at install time |
| `HERDR_PORTAL_ENABLE_AGENT_DECISION` | unset (off) | `1` enables `agent_decision`; any other value leaves it off. `portalctl install` copies it into the portal LaunchAgent (not the tunnel's) only when set to `1` at install time |
| `HERDR_PORTAL_ENABLE_HISTORY` | unset (off) | `agents` (or `1`) lets `pane_read` return `recent` and `recent_unwrapped` for panes that host a recognized agent; `all` adds plain panes, whose scrollback can hold keys and tokens. Any other value is off, is logged at start and reads `invalid` in `GET /api/health`. See [control.md](control.md) |
| `HERDR_PORTAL_ENABLE_CONTROL` | unset (off) | `1` enables `pane_scroll` and `pane_click`; any other value leaves them off |
| `HERDR_PORTAL_ENABLE_AGENT_CLICK` | unset (off) | `1` also allows `pane_click` on a pane that hosts an `idle` or `done` agent. It counts only while `HERDR_PORTAL_ENABLE_CONTROL` is `1` |
| `HERDR_PORTAL_TAG_PANES` | unset (off) | `1` makes the portal set a display-only tag on each pane it sends, or may have sent, input to (`prompt sent 14:07`, token `tunnel_last`) for Herdr's sidebar. Any other value leaves it off. `portalctl install` copies it into the portal LaunchAgent when set. See [plugin.md](plugin.md) |
| `HERDR_PORTAL_HISTORY_TIMEOUT_MS` | `30000` | How long a history read of an agent pane may take before `504 history_timeout` |
| `HERDR_PORTAL_CONTROLLER_LIFETIME_MS` | `5000` | How long a scroll or click controller may live before it is stopped with `SIGTERM` |
| `HERDR_PORTAL_CONTROLLER_KILL_GRACE_MS` | `1000` | How long after that `SIGTERM` the controller gets before `SIGKILL` |
| `HERDR_PORTAL_LAUNCHCTL`, `HERDR_PORTAL_LSOF` | `/bin/launchctl`, `/usr/sbin/lsof` | Which `launchctl` and `lsof` `portalctl` runs. They exist so tests can substitute fakes; leave them unset |
| `HERDR_PORTAL_SIZE_TOOL_TIMEOUT_MS` | `3000` | How long the pane-size read waits for `ps` or `stty` before it refuses the click or scroll as `size_unverified (timed out)` |
| `HERDR_PORTAL_PS_BIN`, `HERDR_PORTAL_STTY_BIN` | `/bin` or `/usr/bin` | Where the pane-size read finds `ps` and `stty`. They exist so tests can substitute fakes; leave them unset |

A timeout variable (`HERDR_PORTAL_HISTORY_TIMEOUT_MS`, `HERDR_PORTAL_CONTROLLER_LIFETIME_MS`, `HERDR_PORTAL_CONTROLLER_KILL_GRACE_MS`, `HERDR_PORTAL_SIZE_TOOL_TIMEOUT_MS`) that is not a whole number of milliseconds above 0 is ignored and the default applies.

Directories, variables and launchd labels keep the project's earlier internal name, `herdr-portal`, so existing installs keep their token, ledger and audit log. `portalctl install` copies the port, `HERDR_BIN` and, when set at install time, `HERDR_PORTAL_STATE_DIR`, `HERDR_PORTAL_LOG_DIR`, `HERDR_PORTAL_HOSTS`, `HERDR_PORTAL_TUNNEL_METRICS`, `HERDR_PORTAL_DROP_DIR` and `CLOUDFLARED_BIN` into the LaunchAgents, plus `HERDR_PORTAL_ENABLE_AGENT_DECISION=1`, `HERDR_PORTAL_STRICT_VERSION=1`, `HERDR_PORTAL_ENABLE_HISTORY` (`1`, `agents` or `all`), `HERDR_PORTAL_ENABLE_CONTROL=1` and `HERDR_PORTAL_ENABLE_AGENT_CLICK=1` into the portal's only. A value the portal would not understand (`HERDR_PORTAL_ENABLE_HISTORY=yes`, say) is not copied. The plist is rewritten on every install, so a switch not set at install time is dropped from it. A loaded job keeps the definition and environment it was loaded with; `start` and `restart` (kickstart) do not reread the plist. `install` over a loaded job therefore boots it out, waits up to 10 s until launchd no longer has it, writes the new plist and bootstraps it, then waits up to 10 s for a new portal instance (a new `build.instance_id` on authenticated `GET /api/health`) that reports the flags and `capabilities` this install set. Any failure exits nonzero and says the state: a failed bootout leaves the old job and plist; a failed bootstrap leaves the service stopped. A fresh install (nothing loaded) is not health-checked; run `portalctl status` or read `build.flags`. `install` and `status` send the token only to a listener on the port that runs as this user (checked with `lsof`); otherwise they say so and send nothing, and `install` fails.

## Running as a service (macOS)

`bin/portalctl install` checks first and writes nothing if a check fails: `herdr` must resolve to an absolute, executable path that runs `--version` under launchd's minimal environment, and the port must be free unless this label already holds it. It then writes the portal's user LaunchAgent and, only when `cloudflared` resolves to an absolute executable, the tunnel's, and starts them. Services are per user, never root. `portalctl plist portal` prints the definition without installing anything. Other commands: `start`, `stop`, `restart`, `status`, `diagnose` (a read-only report on the tunnel, below), `url`, `logs`, `token-copy` (token to the clipboard, never printed, cleared after 60 s if unchanged), `rotate-token`, `revoke` (stops the tunnel job and replaces the token), `uninstall`.

`bin/portalctl diagnose` is read-only and reads no token. It prints whether the portal answers and how many connections the tunnel has, the time of the last request the portal handled and of the last audit entry, and the outages in the last 24 hours (stretches in which the tunnel had no connection to Cloudflare), each with its first error. It reads the connector's log: `HERDR_PORTAL_TUNNEL_LOG` if set, otherwise whichever of the portal's own `tunnel.log` and the cloudflared service's log was written to last. A log that cannot be read is reported as such, not as a quiet day. On macOS it adds the default network and the sleep and wake events; elsewhere those lines say they are not available. It prints no URL and no tunnel hostname, but it does show this machine's gateway and address, so read it before you paste it anywhere. See [when the public address stops answering](tunnel.md#when-the-public-address-stops-answering).

### A second instance or a migration

If the port is taken, install a fresh instance with its own `HERDR_PORTAL_PORT`, `HERDR_PORTAL_STATE_DIR`, `HERDR_PORTAL_LOG_DIR` and `HERDR_PORTAL_LAUNCHD_PREFIX`. Install never renames, copies or rotates existing state; moving an instance to new paths or labels is a manual step.
