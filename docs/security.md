# Security model

⚠️ **The token is as powerful as a shell on this machine.** Herdr's socket can type into any pane, and the portal passes some of that on: `pane_run` types a command line into any shell pane and `agent_prompt` instructs any idle, done or working agent. With the owner's opt-ins on, it also reads whole chats and plain-pane scrollback and scrolls and clicks inside panes ([control.md](control.md)). `put_file` also lets a caller write text files into the drop root (never anywhere else, never executable). Hand the token over through a password manager, never through chat.

- **Pane text is untrusted input.** Whatever a pane shows was written by an agent or a program, and the portal returns it with ANSI escape codes stripped but otherwise unchanged. A pane can print text that looks like a dialog or an instruction.
- **History, scroll and click are off until the owner turns them on, each by its own switch** (`HERDR_PORTAL_ENABLE_HISTORY`, `HERDR_PORTAL_ENABLE_CONTROL`, `HERDR_PORTAL_ENABLE_AGENT_CLICK`; `GET /api/health` shows the effective values under `capabilities`). When on they are on for every caller and every pane. Every history read leaves an audit line with the pane, the source and the size, never the text; it does not name the caller, because there is one token. `HERDR_PORTAL_ENABLE_HISTORY=agents` is the least a caller needs; `all` also returns plain-shell scrollback, where keys and tokens may sit. A history read of an agent pane makes Herdr page that agent briefly, which is why it is allowed only while the agent is `idle` or `done`. A history read is refused with `503 audit_unavailable` when the audit log cannot be written, as a write is; the read that first finds the log unwritable is dropped, not returned.
- **A click does whatever the program under it does with a click.** `pane_click` is bound to what the caller saw (the expected text must still be under the cell when the click is sent) and refuses confirm and refuse words anywhere on the row, rows that look like a menu choice, recognized dialogs and rows it cannot map to a cell. Those checks are pattern matching, not an understanding of the program: a menu in a shape they do not know can be clicked. A working agent can raise a dialog between the screen read and the click, which is why a click on an agent pane is a third switch and only for an `idle` or `done` agent. [Details](control.md#click).
- **The terminal controller.** A click, or a scroll of a pane without Herdr scrollback, opens one short-lived `herdr terminal session control` process, started with an argument array and a clean environment, never with takeover and never resized. The portal reads the terminal's size with `ps` and `stty` by absolute path, also with a clean environment. Pane text never reaches the ledger or the audit log, except the option label `agent_decision` chose, which is text from the agent's own dialog. What was not measured: how a click interleaves with keystrokes of the owner typing at that moment.
- **Put an identity check in front of the hostname before you turn on control.** The token is one secret. A Cloudflare Access policy in front of the tunnel makes a request prove who it is before the portal ever sees the token; see [tunnel.md](tunnel.md#access-in-front-of-the-hostname). This project does not configure or test it.
- **`put_file` writes files, inside one directory.** The drop root (`HERDR_PORTAL_DROP_DIR`) is the only place it writes. Paths are checked name by name (no `..`, no dot-files, a short character set), every existing component is `lstat`ed and a symlink anywhere is refused, files are created exclusively without following links, mode 0600, never executable, and the portal never runs or reads them back to anyone but the caller of that request. Whatever else on the machine reads the drop root (an agent told to "read this file") treats its content as untrusted input. Residual risk: a local process that can already write inside the drop root can race the checks; the root must be owned by the portal user and closed to others (`503 drop_root_unsafe` otherwise). Do not point `HERDR_PORTAL_DROP_DIR` at a directory you do not want a caller to fill: up to 256 KiB per file, no quota on the number of files.
- **`agent_decision` is off by default.** `HERDR_PORTAL_ENABLE_AGENT_DECISION=1` in the portal's environment turns it on. That is an operator choice, not a safety certification. When on, it is on for every caller and every pane. Its refuse list is keyword matching, so a dialog that passes is not thereby safe. Options that grant standing permission ("always allow", "switch to auto mode") are answerable. The caller names an option, not the dialog it inspected, so a late request can answer a dialog that replaced it. `portalctl install` copies it into the portal's LaunchAgent only if you set it to `1` when you run install. [Details](agent-decision.md#what-it-cannot-promise).
- **The audit log is a record, not tamper evidence.** It is a local 0600 file the same user can edit; it records write actions, `put_file` calls and history reads only (screen reads and calls refused as `action_disabled` are not logged), stores no prompt, command text or file content, and is never rotated.
- **Auth.** Every `/api/*` request needs `Authorization: Bearer <token>`: 32 CSPRNG bytes in a 0600 file, compared as SHA-256 digests in constant time. Eight failed attempts per client per five minutes lock that client out; requests are capped at 240 per minute, keyed on the `CF-Connecting-IP` header, which any local process can set. The `Host` header must be `127.0.0.1`, `localhost`, a `*.trycloudflare.com` name, a name in `HERDR_PORTAL_HOSTS` or the named tunnel's hostname, and a request with an `Origin` must come from the same host. The browser UI keeps the token in memory only.

## Residual risks

What the portal does not defend, so you can decide what to switch on:

- **One token, no scopes.** Whoever holds it can call every action that is switched on, on every pane. Per-action or per-pane tokens do not exist.
- **The click guard is pattern matching.** A menu in a shape the patterns do not know can be clicked when control is on. Keep control off unless something that authenticates people sits in front of the hostname ([tunnel.md](tunnel.md)).
- **Wheel events change what an app highlights.** A scroll is refused while a recognized dialog is on the screen; an unrecognized menu that turns a wheel notch into an arrow key moves its highlight, and the owner's next Enter then picks another option.
- **A prompt to a working agent can land on a dialog that appeared a moment earlier.** `agent_prompt` accepts a `working` agent and answers `input_sent_queued`. Herdr refuses a prompt for an agent it already classifies as `blocked` (`agent_blocked`), and the portal refuses a `blocked` or `unknown` agent and a working agent whose screen shows a dialog it recognizes (`dialog_on_screen`). A dialog in a shape the parser does not know, or one raised after the screen read and before Herdr's classification catches up, receives the text and its Enter, which can pick the highlighted option. No portal action answers a dialog on purpose except `agent_decision`, which is off. Nothing here was measured on a real agent mid-turn.
- **A working agent can raise a dialog between the screen read and the click.** That is why a click on an agent pane is a third switch and only for an `idle` or `done` agent.
- **History reads can read secrets.** `HERDR_PORTAL_ENABLE_HISTORY=all` returns plain-shell scrollback, where keys and tokens may sit. Each read is audited, but the audit line does not name a caller.
- **Paging an agent is an action on it.** A history read of an agent pane makes Herdr page that agent briefly. Whether Herdr also pages a full-screen app it has not yet recognized as an agent was not measured.
- **Queued reads wait on the pane lock.** Each history read of an agent pane can hold it for up to 30 s, and nothing caps how many queue behind it.
- **The ledger and the audit log are never rotated.** Every unique idempotency key adds a row.
- **The owner typing while a controller is attached** was not measured ([control.md](control.md#not-covered)).
