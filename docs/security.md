# Security model

⚠️ **The token is as powerful as a shell on this machine.** Herdr's socket can type into any pane, and the portal passes some of that on: `pane_run` types a command line into any shell pane and `agent_prompt` instructs any idle agent. `put_file` also lets a token holder write text files into the drop root (never anywhere else, never executable). Hand the token over through a password manager, never through chat.

- **Pane text is untrusted input.** Whatever a pane shows was written by an agent or a program, and the portal returns it with ANSI escape codes stripped but otherwise unchanged. A pane can print text that looks like a dialog or an instruction.
- **`put_file` writes files, inside one directory.** The drop root (`HERDR_PORTAL_DROP_DIR`) is the only place it writes. Paths are checked name by name (no `..`, no dot-files, a short character set), every existing component is `lstat`ed and a symlink anywhere is refused, files are created exclusively without following links, mode 0600, never executable, and the portal never runs or reads them back to anyone but the caller of that request. Whatever else on the machine reads the drop root (an agent told to "read this file") treats its content as untrusted input. Residual risk: a local process that can already write inside the drop root can race the checks; the root must be owned by the portal user and closed to others (`503 drop_root_unsafe` otherwise). Do not point `HERDR_PORTAL_DROP_DIR` at a directory you do not want a token holder to fill: up to 256 KiB per file, no quota on the number of files.
- **`agent_decision` is off by default.** `HERDR_PORTAL_ENABLE_AGENT_DECISION=1` in the portal's environment turns it on. That is an operator choice, not a safety certification. When on, it is on for every token holder and every pane. Its refuse list is keyword matching, so a dialog that passes is not thereby safe. Options that grant standing permission ("always allow", "switch to auto mode") are answerable. The caller names an option, not the dialog it inspected, so a late request can answer a dialog that replaced it. `portalctl install` copies it into the portal's LaunchAgent only if you set it to `1` when you run install. [Details](agent-decision.md#what-it-cannot-promise).
- **The audit log is a record, not tamper evidence.** It is a local 0600 file the same user can edit; it records write actions and `put_file` calls only (reads and calls refused as `action_disabled` are not logged), stores no prompt, command text or file content, and is never rotated.
- **Auth.** Every `/api/*` request needs `Authorization: Bearer <token>`: 32 CSPRNG bytes in a 0600 file, compared as SHA-256 digests in constant time. Eight failed attempts per client per five minutes lock that client out; requests are capped at 240 per minute, keyed on the `CF-Connecting-IP` header, which any local process can set. The `Host` header must be `127.0.0.1`, `localhost`, a `*.trycloudflare.com` name, a name in `HERDR_PORTAL_HOSTS` or the named tunnel's hostname, and a request with an `Origin` must come from the same host. The browser UI keeps the token in memory only.
